# Deerly / LAB — 14 天放鬆練習：LINE 體驗與視覺設計規格

> 2026-10-25，供 Codex 接手實作和評審。**不代表已部署或已對外販售。**
> 第一版僅限「14 天放鬆練習」；第二款 7 天重要場合訓練本輪不動。

## 1. 品牌依據：以現有 Deerly 為基礎，而不是重新設計成冥想 App

來源：
- `engine/menugen.mjs`：現有 LINE Rich Menu 色票、字體與卡片樣式
- `engine/style.css`：LIFF 問卷色票、字級、按鈕與觸控尺寸
- `index.html`：rPPG 的量測流程、提示與 CTA
- `menus/`：現有視覺資產

### 色票（直接沿用現有品牌）

| Token | 色碼 | 用途 |
|---|---|---|
| Canvas / 奶油底 | `#F6F1EA` | 品牌卡片背景、圖文選單大面積底色 |
| Surface / 白 | `#FFFFFF` | 資訊卡片 |
| Forest / 主綠 | `#2F7D5B` | 品牌、重要操作、標題點綴 |
| Deep forest / 深綠 | `#1F5C42` | 重要按鈕、需要高對比時 |
| Text / 墨綠黑 | `#1E2A24` | 主要文字 |
| Sage / 淺綠 | `#E4EDE7` | 次要區塊、選取狀態 |
| Line / 暖灰 | `#E3DACB` | 區塊邊框、進度底線 |

避免把低對比的 `#7A8780` 直接用於白底 14px 的重要文字（小字測試對比不足）；改用更深的輔助文字如 `#52655B`，正式實作前檢查 WCAG AA 對比度。深綠按鈕＋白字提供主要 CTA。

### 視覺氣質

- 關鍵詞：溫暖、乾淨、沉穩、像可信任的生活服務；**非醫療儀表板、非玄學、非過度少女風**。
- 首批假設客群：忙碌上班族（原先產品構想以 28–38 歲女性為初步核心）。年齡與性別只是待驗證的行銷假設，不應採用刻板印象設計。
- 一個畫面只傳達一件事。第一屏：服務解決什麼問題、需要多久、下一步是什麼。
- 中文繁體、台灣口語：用「每天花 3–10 分鐘」「放鬆練習」「看看自己的心率」，不說「治癒焦慮」「降低壓力指數」「科學測出你的情緒」。

## 2. 正確的平台分工

- **LINE Messaging API 聊天室為使用者主場**：啟動、同意、5 題問答、返回、結果預覽、意願、未來每日提醒。
- **LIFF 只負責需要前鏡頭的 rPPG 量測**，量完回到 LINE 聊天室接續。
- **Supabase Edge Function**：狀態機、LINE Webhook、隱私同意記錄、問卷預覽、意願記錄。
- **GitHub Pages**：既有 LIFF 相機頁／LINE Rich Menu 圖片託管；不是另開一個對外銷售網站。
- 不加入 Cloudflare、不新開第二個 LINE 官方帳號、不修改正式保健品選單或金流。

### LINE 可控與不可控

可以自訂：Flex Message 卡片版型、圖文選單（Rich Menu）圖片、LIFF 網頁的字體／色彩、品牌素材和訊息文案。
不能當作自訂：LINE 原生聊天背景、所有原生對話泡泡的背景色、原生 Quick Reply 按鈕的視覺細節。
因此**不要**承諾整個 LINE App 都能套用 Deerly 配色。

## 3. 建議訊息架構（不要堆文字牆）

1. **歡迎／說明卡**（Flex 單張卡）：`14 天放鬆練習`，一句話價值、`5 題／約 1 分鐘`、`心率量測可略過`、CTA「開始」
2. **五題互動**：一題一則訊息，選項以 LINE Quick Reply（易測版）呈現。若實機可用性不好，再考慮產生專屬 Rich Menu 圖片；不得覆蓋既有保健品選單，也需處理返回預設選單。
3. **rPPG 選用卡**（Flex）：`用前鏡頭看看心跳`、估計 30 秒、原始影像只在量測頁處理、明示「不量也能取得相同方案」；主 CTA「開始心率量測」，次 CTA「略過」
4. **結果卡**（Flex）：`你的 14 天放鬆計畫`、`每天 5 分鐘`、`適合下班後` 等來自問卷的可信個人化原因，不把心率推成焦慮診斷。
5. **價格意願卡**（Flex）：方案預覽 Day 1–2、測試價 NT$1,290，清楚標示「尚未開放購買／不會扣款」。
6. **未來付費後提醒**：只在真實付款成功且同意接收時才實作。初期不能假裝完整課程已可交付。

### 主要文案參考

歡迎：
「忙完一整天，也許可以為自己留 5 分鐘。先回答 5 個小問題，我們替你整理一份容易開始的 14 天放鬆練習。心率量測可自由選擇。」

心率：
「不用穿戴裝置，也能用手機前鏡頭看看當下的心率。這不是壓力、情緒或疾病診斷；你可以直接略過，不影響專屬練習安排。」

結果：
「依你的回答，你比較適合在『下班後』安排練習，從每天『5 分鐘』開始。讓我們先試前兩天。」

## 4. 手機體驗與視覺細節

- 目標設計寬度：390px 的 iPhone 視窗，另驗證 360px Android。要配合 LINE 字體放大與深色模式。
- 每則引導最多 1–3 短段落；問題文案 30 字左右；選項通常 2–4 個、保持好點擊。
- Flex 卡片只用 1 個醒目的 CTA；其他輔助動作改為中性按鈕。保留一致留白、適中圓角、清楚的 1/5 進度文字。
- 結果應有「依哪個回答而客製化」的透明依據，不因為量到心率就推測使用者的壓力程度。
- 量測失敗必須可以直接略過，不讓使用者卡關。
- 色彩只是輔助；對比度、焦點／朗讀順序、可理解的按鈕文字和載入／失敗回饋優先。
- 不要使用誇大健康宣稱；放鬆流程不要求憋氣或激烈呼吸調節。

## 5. Codex 要先完成的實作

P0 — 程式品質：
- 閱讀 PR #31 的試驗分支，執行 `node pilot/test.mjs`、`node backend/linebot/build.mjs`。
- 靜態驗證/測試 `backend/linebot/index.ts`：確保問卷 5 題、回上題、恢復、中止、同意、刪除、錯誤處理、白名單與保健品問卷隔離。
- 增加自動化測試或模擬 LINE Webhook，不存取生產環境。
- 測試已有問卷狀態與新問卷同時存在時的正確行為，避免動態 Rich Menu 覆蓋。
- 留意 LINE Webhook 重送事件和重複點擊，需可重入且不重複產生非預期結果。

P1 — 介面：
- 新增可重用的 Flex Message 建構器，先做歡迎、rPPG 量測選項、結果、價格意願四張卡。
- 以現有品牌色票與 LINE Flex Message 限制設計，產生可在 LINE Flex Message Simulator 測試的有效 JSON。
- 使用與原 Deerly 一致的語氣。**勿改正式 Rich Menu 主選單**。
- 提供 iOS/Android 的截圖與手動實機檢查清單；若環境無模擬器或不能拍截圖，明確標示未完成，不能宣稱已實測。

P2 — 後端與部署準備（非正式部署）：
- 審查 `backend/schema-digital-relax-pilot.sql` 的專案相容性，確認保健品資料表不受影響。
- 產生可重複執行且易回滾的測試資料表操作程序。
- 整理 Supabase Secrets 和白名單清單；**不要把實際 Token/Secret 提交至 GitHub**。
- 檢查新增的資料保存與刪除策略，既有 rPPG 量測同意和放鬆問卷同意不能混用。
- 最後給出：哪些測試已執行、哪些仍需要使用者手機或服務權限、是否能進入「受邀用戶測試」。

## 6. 驗收標準

- 在 LINE 聊天室完成五題，不跳外部問卷。
- 資料不會蓋掉既有 `quiz_sessions`、`intakes`、`packs`。
- 相機權限拒絕／光線不足／未同意：皆可略過並順利收到方案。
- 量測後從 LINE 聊天室看到結果；只展示可靠度符合門檻且屬於本次的新紀錄。
- LINE 卡片外觀與 Deerly 原本視覺一致，不過度醫療化。
- 尚未完成收款時，每個畫面皆不得暗示已付款或商品已交付。
- 既有保健品流程在測試後仍正常。
- 沒有任何未經核准的正式部署或正式資料修改。
